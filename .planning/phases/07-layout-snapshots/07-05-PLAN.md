    ```go
    package layout

    import (
        "context"
        "log/slog"
        "time"
    )

    // RunPrune launches a goroutine that prunes raw layout_snapshots older than
    // retention every interval. Per CONTEXT.md D-01, retention = 7 days and
    // interval = 6 hours (small enough that prune drift is bounded; large enough
    // that the 60s capture loop never contends). Returns when ctx is done.
    func RunPrune(ctx context.Context, store *Store, retention, interval time.Duration, logger *slog.Logger) {
        // Run once shortly after start to clear any backlog from a previous session.
        time.Sleep(15 * time.Second)
        run := func() {
            deleted, err := store.Prune(retention)
            if err != nil {
                logger.Warn("layout prune failed", "error", err)
                return
            }
            if deleted > 0 {
                logger.Info("layout prune", "deleted_rows", deleted, "retention_hours", retention.Hours())
            }
        }
        run()
        ticker := time.NewTicker(interval)
        defer ticker.Stop()
        for {
            select {
            case <-ctx.Done():
                return
            case <-ticker.C:
                run()
            }
        }
    }
    ```

    Do NOT add a separate test file for this — the goroutine is glue around `Store.Prune`, which is unit-tested in 07-02-PLAN Task 2 (TestStore_Prune7Days). The Three Examples rule applies: this is glue, not a candidate for abstraction.

## Trust Boundaries

- **trasker-client process → local SQLite:** trusted, same UID.
- **trasker-client process → server HTTPS:** authenticated via API key.
- **operator running smoke test → docker compose:** trusted local environment.

## STRIDE Threat Register

- **T-7-05-01 — Tampering (silent failure of layout pipeline):** A bug in the wiring causes the daemon to start without ever invoking layout.Capturer.Start, leading to "everything looks healthy but nothing flows." Disposition: mitigate. Mitigation: the manual smoke test in Task 3 step 2 explicitly verifies that a row appears in local SQLite within 60s. No-row-after-60s = wiring bug = checkpoint fails.
- **T-7-05-02 — Information disclosure (titles in logs):** Wiring at debug-level could log the windows array. Disposition: mitigate. Mitigation: 07-02-PLAN Task 3 grep-checks that sync.go does not log the windows payload at INFO/WARN. Smoke test step 7 spot-checks logs for any line containing a real window title.
- **T-7-05-03 — Denial of service (orphaned goroutine):** ctx cancellation during shutdown should stop the capturer + syncer + pruner. Disposition: mitigate. Mitigation: each goroutine (capturer.Start, syncer.Start, RunPrune) checks ctx.Done(); defer-stops are added in main.go.
- **T-7-05-04 — Tampering (no-DISPLAY crash):** trasker-client running on a remote box with no DISPLAY env shouldn't crash. Disposition: mitigate. Mitigation: enumerator returns ErrUnsupported in that case (or the X11Enumerator constructor returns an error from XOpenDisplay nil); the wiring gates on that error and logs Warn instead of starting the goroutines.
- **T-7-05-05 — Information disclosure (smoke test reveals real window titles):** Step 6/7 of the manual smoke test will display the operator's real window titles. Disposition: accept. Rationale: it's Jaypaul's own machine and own dashboard. Note: do NOT paste those titles into the Task 3 report — share row counts and shape, not content.
</threat_model>
