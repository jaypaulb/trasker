```sql
CREATE TABLE layout_snapshots (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    device_id    UUID NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
    captured_at  TIMESTAMPTZ NOT NULL,
    windows      JSONB NOT NULL,
    windows_hash TEXT NOT NULL,
    tier         TEXT NOT NULL DEFAULT 'raw',
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT chk_layout_tier CHECK (tier IN ('raw', '10min', '1hr'))
);
CREATE INDEX idx_layout_snapshots_device_captured ON layout_snapshots (device_id, captured_at DESC);
CREATE INDEX idx_layout_snapshots_tier_captured  ON layout_snapshots (tier, captured_at);
CREATE UNIQUE INDEX idx_layout_snapshots_dedup   ON layout_snapshots (device_id, captured_at, windows_hash);
```

<threat_model>
## Trust Boundaries

- **client-daemon → server API:** authenticated channel via existing API-key auth (Authorization: Bearer). Layout payloads cross this boundary as JSONB.
- **operator psql session → Postgres:** trusted (host operator with credentials). Manual migration application path for existing deployments.
- **fresh Postgres volume init → docker-entrypoint-initdb.d:** trusted local file mount; runs once on empty volume.

## STRIDE Threat Register

- **T-7-01-01 — Tampering:** Hand-modified DDL drift between `migrations/004_layout_snapshots.up.sql` and `deploy/initdb/001_schema.sql`. Disposition: mitigate. Mitigation: both files contain the same `CREATE TABLE` block verbatim; CI byte-compare in a future phase. For Phase 7 we accept manual-discipline; the verify step in Task 3 visually confirms the block.
- **T-7-01-02 — Information disclosure (privacy invariant):** Adding any field beyond `app_name + window_title + x + y + w + h` to the JSONB or to top-level columns (PID, cmdline, display index, screenshot, z-order) leaks more than D-16 permits. Disposition: mitigate. Mitigation: explicit grep gate in acceptance criteria for both up.sql and initdb append; plan-checker rejects any PR that re-adds these.
- **T-7-01-03 — Denial of service (FK on cascade):** `ON DELETE CASCADE` from `devices` means deleting a device wipes its snapshots. Acceptable per scope: snapshots belong to the device. Disposition: accept. Rationale: Phase 9 dogfooding will exercise device deletion; we want orphan-free state.
- **T-7-01-04 — Tampering (migration not applied to existing deployment):** Operator forgets to run `psql -f migrations/004` against an existing deployed instance. Server starts, `/api/v1/layout-snapshots` returns 500 with `relation "layout_snapshots" does not exist`. Disposition: mitigate. Mitigation: 07-04-PLAN handler logs a clear error and returns 503 with a body that says "schema not migrated; apply migrations/004_layout_snapshots.up.sql"; documented as A2 in RESEARCH.md.
- **T-7-01-05 — Tampering (ROADMAP drift):** ROADMAP.md success criteria become stale relative to v1 scope, future plans implement v2 features and break privacy invariant. Disposition: mitigate by Task 1 amendment now; checker enforces forward.
</threat_model>
