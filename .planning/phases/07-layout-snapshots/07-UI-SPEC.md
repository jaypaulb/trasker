# Phase 7 — UI Design Contract: Layout Snapshots

> Visual and interaction contract for the new `/layout` route in the server-ui SvelteKit dashboard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **one new route** (`/layout`) to an existing dashboard with a fully established design system. The dominant principle is **conform, don't invent** — every token, color, and pattern below is mirrored from existing sibling routes (`/devices`, `/team`, `/admin/audit`) verified in the codebase. New ground is limited to: copywriting for the layout-specific UI, the timestamp-list interaction shape (D-10), and the empty-state copy.

---

## Surface Scope

This contract covers exactly one screen and one nav addition:

- **New route:** `web/server-ui/src/routes/(app)/layout/+page.svelte` plus `+page.ts` loader.
- **Nav addition:** one entry appended to `navItems` in `web/server-ui/src/lib/components/Sidebar.svelte`. NOT to `(app)/+layout.svelte` — that file delegates nav to `Sidebar.svelte`.
- **API extension:** `layout` namespace added to `src/lib/api.ts` (timeline + at). Type-shape contract only; not a visual surface.

Out of scope for this contract (locked by CONTEXT.md D-10 through D-13): timeline scrubber, calendar picker, geometry mosaic, multi-device merge UI, window-title search bar, real-time updates, export.

---

## Design System

- **Tool:** none (no shadcn). Adding shadcn for one route would violate scope; the existing dashboard does not use it and Tailwind v4 is already in place.
- **Preset:** not applicable.
- **Component library:** none — bespoke Svelte components composed from Tailwind utilities, matching the established sibling-route pattern.
- **CSS engine:** TailwindCSS v4 via `@tailwindcss/vite` (verified in `web/server-ui/package.json` and `vite.config.ts`). No `tailwind.config.js`; design tokens live in `src/app.css` as CSS custom properties.
- **Dark mode:** enabled via the project's `.dark` class strategy (`@custom-variant dark (&:where(.dark, .dark *))` in `app.css`). The `theme` store at `$lib/stores/theme` toggles `<html class="dark">`. The new route MUST mirror existing sibling routes' `dark:` class pairings — light-only would render as a white hole inside an otherwise dark-mode-aware shell.
- **Icon library:** inline `<svg>` paths matching the Heroicons-outline style already used in `Sidebar.svelte`. No icon dependency added. Stroke width 1.5, viewBox 24×24, `fill="none" stroke="currentColor"`.
- **Font:** system default sans (`@apply ... font-sans` in `app.css`). No web font added.

## Spacing Scale

Tailwind v4 default scale (multiples of 4) is in effect. The existing sibling routes use a narrow subset; the new route MUST stick to that subset.

- **xs — 4px (Tailwind `1`):** never used standalone in sibling routes; reserved.
- **sm — 8px (Tailwind `2`):** inline gaps between text + icon (e.g. `gap-2` in Sidebar nav links and Header user menu).
- **md — 16px (Tailwind `4`):** card-internal vertical rhythm; inter-item gaps inside row groups.
- **lg — 20px (Tailwind `5`):** card body padding (`p-5` is the established cell padding for table rows in `/devices` table; use this for the timestamp-row hit target).
- **xl — 24px (Tailwind `6`):** section-to-section vertical gap inside the page (`space-y-6` is used by `/devices` and `/admin/users` page roots — use this verbatim).
- **2xl — 32px (Tailwind `8`):** never used standalone in sibling routes; reserved.
- **3xl — 64px (Tailwind `16`):** never used at this dashboard scale; reserved.

Page main padding is fixed by `(app)/+layout.svelte` `<main class="p-6">` — do NOT add page-edge padding inside `+page.svelte`. Start the page with `<div class="space-y-6">`, the same pattern as every sibling route.

**Exceptions:** none. This route uses only the spacing tokens already in use.

## Typography

Verified from `app.css` (system sans, default Tailwind sizes) and the actual classes used across `/devices`, `/+page.svelte`, `/admin/users`, `/team`. The dashboard uses **four** type roles, NOT three or five:

### Body — 14px (Tailwind `text-sm`), weight 400, line-height ~1.43 (Tailwind default)

- Used for: row content inside the timestamp list, expanded window-detail text, helper paragraphs.
- Color: `text-gray-700 dark:text-gray-300` for primary body, `text-gray-500 dark:text-gray-400` for secondary helper text.
- Established in sibling routes' table rows and `<p>` helper text.

### Label — 12px (Tailwind `text-xs`), weight 400, line-height ~1.33

- Used for: timestamp metadata (`window count`, `device name` annotations), table column headers, code-monospace `device_id` shortenings.
- Color: `text-gray-500 dark:text-gray-400` for header-like labels, `text-gray-400 dark:text-gray-500` for tertiary metadata (the dimmer of the two grays).
- Established in `/devices` table headers and `/+page.svelte` recent-submissions metadata.

### Heading — 18px (Tailwind `text-lg`), weight 600 (`font-semibold`), line-height ~1.55

- Used for: section card titles like "Today's snapshots" or "Snapshot details".
- Color: `text-gray-900 dark:text-white`.
- Established in `/devices` card titles ("Download Trasker Client", "Registered Devices").

### Display — 24px (Tailwind `text-2xl`), weight 700 (`font-bold`), line-height ~1.33

- Used for: the page title ("Layout Snapshots") at the top of `+page.svelte`.
- Color: `text-gray-900 dark:text-white`.
- Established at the top of every sibling route's `+page.svelte`.

**Weights in use: exactly two** — 400 (default body/label) and 600/700 for emphasis (semibold for card titles, bold for the page title). No medium, no extralight, no extrabold.

**Line height:** Tailwind defaults are inherited (no explicit `leading-*` overrides in sibling routes); the established practice is to accept Tailwind's per-size defaults. Do not introduce custom `leading-*` classes.

**Numeric tabular alignment:** timestamp values like `14:32:07` should use `font-mono text-xs` (matches the `/devices` table's `device_id` short-hash treatment) so columns align visually when stacked. This is the only mono usage in the new route.

## Color

The dashboard's 60/30/10 split is established. The new route MUST use the same palette; it MUST NOT introduce a new accent or semantic hue.

### Dominant (60%) — page surface

- Light: `bg-slate-50` on the app shell `<div>` in `(app)/+layout.svelte`. Inside the page, the `<main>` inherits this — do NOT set a background on the page root.
- Dark: `bg-slate-950` (already on the shell).
- Source: `(app)/+layout.svelte` line 8 — `class="flex min-h-screen bg-slate-50 dark:bg-slate-950"`.

### Secondary (30%) — cards, sidebar, table

- Cards: `bg-white dark:bg-slate-800` with `rounded-lg shadow-sm border dark:border-slate-700`. This exact class string is repeated verbatim across `/devices`, `/+page.svelte`, `/admin/*` — copy it.
- Sidebar (navigation column): `bg-slate-800 dark:bg-slate-900` (already in `Sidebar.svelte`; the new nav link inherits this).
- Header bar: `bg-white dark:bg-slate-800 border-b border-gray-200 dark:border-slate-700` (already in `Header.svelte`).
- Table header strip: `bg-gray-50 dark:bg-slate-700/50` (matches the `/devices` table).
- Row hover (for the click-to-expand timestamp rows): `hover:bg-gray-50 dark:hover:bg-slate-700/50`. Mirror the `/admin/users` row-hover convention.

### Accent (10%) — blue, reserved use only

- Hex / Tailwind: `bg-blue-600` solid (e.g. active sidebar link) and `text-blue-600 dark:text-blue-400` for inline link/affordance text. CSS var `--color-primary: #2563eb` in `app.css` corresponds.
- **Accent is reserved EXCLUSIVELY for:**
  - The "Layout" link in the sidebar when active (`bg-blue-600 text-white` when on `/layout`, matching the existing `isActive` check in `Sidebar.svelte`).
  - The expand/collapse caret icon (uses `currentColor`; defaults to gray, no special accent here — DO NOT bluify the caret).
  - A loading spinner border (`border-blue-600`, exactly as in `/+page.svelte` line 74).
  - Inline action affordances (the `Open permalink` text button, if added — `text-blue-600 dark:text-blue-400 hover:text-blue-800 dark:hover:text-blue-300` — same treatment as Devices page's `Rename` button).
- **Accent is FORBIDDEN for:** all timestamp rows, all body text, all card borders, all section dividers, all primary/empty/error state copy. The view is intentionally calm; blue is the exclamation point, not the paragraph.

### Destructive — `text-red-600 dark:text-red-400`

- Reserved for the API/load error banner only (matching `/devices` error display: `class="p-5 text-red-600 dark:text-red-400"`).
- v1 has NO destructive actions on this surface: snapshots are read-only here. Therefore: no destructive confirmation dialog is needed for this phase. If a "delete snapshot" affordance is ever added (deferred), it must use the existing pattern from `Header.svelte` Sign-out button (`text-red-600 dark:text-red-400 hover:bg-red-50 dark:hover:bg-red-900/20`). For Phase 7, "Destructive confirmation" is **not applicable**.

### Status / informational

- Empty-state and "no data yet" gray: `text-gray-400 dark:text-gray-500` (matches `/devices` empty state and `/+page.svelte` empty state).
- Border on collapsed list dividers: `divide-y dark:divide-slate-700` (exact match for the `/+page.svelte` recent-submissions list).

### Primary CTA

There is no primary CTA on this page. The page is a passive viewer; the user lands and immediately sees data (or empty state). The closest analogue is the timestamp row click — that is **not a CTA**, it is a content interaction. Do not add a button labelled "View" or "Load Snapshot" — this is the kind of scope creep CONTEXT.md D-10 forbids.

### Section card titles

- For the timestamp list card: `Today's snapshots` (when `?t=` is absent).
- For the permalink card: `Snapshot at {ISO}` where `{ISO}` is the literal `t` query value formatted as the user-locale date-time. Example label: `Snapshot at 2026-05-07 14:32:07 UTC`.
- Class for both: `text-lg font-semibold text-gray-900 dark:text-white`, sat inside a card header strip `px-5 py-4 border-b dark:border-slate-700` — exact mirror of `/devices` "Registered Devices" card header.

### Per-row primary text

- **Copy:** the snapshot timestamp formatted in the user's locale, hours/minutes/seconds. Use `new Date(captured_at).toLocaleTimeString(undefined, { hour: '2-digit', minute: '2-digit', second: '2-digit' })` — matches the locale-respecting style in `/devices` `formatDate`.
- Class: `font-mono text-sm text-gray-900 dark:text-white` (mono so columns align across rows).

### Per-row secondary text (window count badge)

- **Copy:** `{n} windows` for n ≠ 1, `1 window` for n = 1. NEVER `1 windows`.
- Class: `text-xs text-gray-500 dark:text-gray-400`.

### Expanded-row window list

- Each window line copy: `{app_name} — {window_title}` joined by an em-dash with single spaces. If `window_title` is empty: just `{app_name}`. If `app_name` is empty (rare X11 case): `{window_title}` alone. Never show `undefined` or `null`.
- Geometry suffix copy: ` · {w}×{h} @ ({x}, {y})` appended in `text-gray-400 dark:text-gray-500 text-xs`. The `×` is the multiplication sign U+00D7, not lowercase `x`.
- Truncation: `truncate` class on the title span; full title surfaces via `title="{full_title}"` HTML attribute on hover.

### Empty state — no snapshots today (default mode, server returned `[]`)

- **Heading copy:** `No snapshots yet today.`
- **Body copy:** `Your client hasn't reported a layout change since midnight. Snapshots are written only when something on your desktop changes — open a window or switch focus, then come back.`
- Layout: centered text inside the card body, `class="px-5 py-8 text-center text-gray-400 dark:text-gray-500"` — exact mirror of `/+page.svelte` "No submissions this week" state.

### Empty state — no device registered

- **Heading copy:** `No client devices registered yet.`
- **Body copy:** `Layout snapshots come from your Trasker client. Download and run the client from the Devices page, then reload this view.` (The word `Devices` SHOULD link to `/devices` using inline accent: `text-blue-600 dark:text-blue-400 hover:text-blue-800 dark:hover:text-blue-300 underline`.)

### Empty state — permalink mode, no snapshot at-or-before `t`

- **Heading copy:** `No snapshot for this moment.`
- **Body copy:** `The earliest snapshot for this device is {first_captured_at_locale}. Try a later timestamp.` If the device has zero snapshots at all: `This device has not reported any snapshots yet.`

### Loading state

- **Copy:** `Loading snapshots...` (verbatim, with three dots — matches `/devices` `Loading devices...`).
- Layout: `class="flex items-center gap-2 text-gray-500 dark:text-gray-400"` with the same spinner pattern as `/+page.svelte` line 73-76 (animated div with `border-blue-600`).

### Error state

- **Banner copy:** the actual error message returned from `api.layout.*` (mirror `/+page.svelte` lines 40-42 — show the real `Error.message`).
- Surrounding chrome copy: none (no "Oops!" prefix, no friendly wrapper). The user wants the truth; the existing dashboard convention is to show raw API messages.
- Class: `bg-red-50 dark:bg-red-900/20 border border-red-200 dark:border-red-800 text-red-700 dark:text-red-400 rounded-lg p-4` — exact mirror of the `/+page.svelte` error block.
- Below the error message, append a single sentence in smaller copy: `Refresh the page to retry.` Class: `text-xs text-red-600 dark:text-red-300 mt-1`. (Server errors here are infrequent; offering a deeper retry workflow is overkill for v1.)

### Permalink share affordance

- **Copy:** `Copy permalink`
- Placement: a small text button at the right of the snapshot card header in permalink mode.
- Class: `text-xs text-blue-600 dark:text-blue-400 hover:text-blue-800 dark:hover:text-blue-300`.
- Behavior: copies `window.location.href` (already includes `?t=...`) to clipboard. After click, label flips to `Copied` for 2 seconds. No toast, no modal.

### Destructive confirmation copy

- **Not applicable** — this surface has no destructive actions in v1. Snapshots are read-only here; client-side prune and server-side downsampling are background processes with no UI affordance. CONTEXT.md and ROADMAP.md confirm.

## Interaction & State Contract

### Page modes (driven by `?t=` query param, matching CONTEXT.md D-11)

- **Mode A — `?t=` absent (default):** Page header reads `Layout Snapshots`. Below is one card titled `Today's snapshots` containing the timestamp list for `[start_of_today_UTC, now]` for the current device. Empty list → "no snapshots yet today" empty state.
- **Mode B — `?t=ISO` present:** Page header still reads `Layout Snapshots`. Below is one card titled `Snapshot at {ISO formatted}` containing exactly one snapshot — the most recent at-or-before `t`. The card header includes the `Copy permalink` text button. If no snapshot exists at-or-before `t`: the permalink-empty state.

### Timestamp-row interaction (Mode A)

- Hit target: the entire row, height ≥ 40px (`px-5 py-3` = 8px+8px on top/bottom around 14px text → 30px content + 16px padding = 46px row height; verified against `/+page.svelte` recent-submissions row).
- Click expands the row to reveal the windows list inline. Re-clicking collapses. Only one row may be expanded at a time — clicking a different row collapses the previously open one. (This matches the lightweight progressive-disclosure pattern from `/devices` `<details>`-style toggles, but implemented with a Svelte `$state` index variable rather than `<details>` because the row header includes structured columns, not a single summary line.)
- Visual cue: a chevron-right glyph on the left of the row that rotates 90° to chevron-down when expanded. Use Heroicons outline path `M8.25 4.5l7.5 7.5-7.5 7.5`. No animation requirement beyond CSS `transition-transform`. Stroke 1.5, color `currentColor` so it follows row text color.
- Keyboard: rows are `<button>` elements (NOT `<div onclick>`) so they receive focus naturally and Enter/Space toggle expansion. Focus ring uses Tailwind's default `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-600` — matches existing implicit button focus in the dashboard.

### Permalink share (Mode B)

- The `Copy permalink` button is the only interactive affordance in this mode beyond the always-visible expanded windows list.
- The single snapshot in Mode B is shown in expanded form by default — there is no row to click; the windows are immediately visible.

### Cross-mode behavior

- Device selection is implicit in v1 (D-12: per-device only). The page picks the first device returned by `api.devices.list()` and uses it for all queries. No device selector UI in Phase 7.
- If `api.devices.list()` returns `[]`: show the "no device registered" empty state, do NOT call the layout endpoints.

### Loading sequence

- On mount: parallel `Promise.allSettled([api.devices.list(), <conditional layout call>])` is the wrong shape because the layout call needs the device id from the devices list. Instead: serial — devices first, then layout. The loader displays the spinner across the full sequence; do not flash a partial empty state between calls.
- Spinner placement: replaces the entire card body, NOT the page chrome. Page header and sidebar stay rendered.

### Responsive behavior

- The dashboard is desktop-first; sibling routes break gracefully at narrow widths but no mobile-specific design exists.
- For this route: the timestamp list card is full-width inside `<main class="p-6">`. Window list rows truncate titles before wrapping. No horizontal scroll target inside the row — long titles ellipsize via `truncate` and surface via `title=` attribute hover.
- No tablet/phone optimization required for v1 — matches sibling-route pattern.

### Accessibility floor

- All interactive elements are real `<button>` or `<a>` — no clickable `<div>`.
- Row chevron has `aria-hidden="true"` (decorative); the row button itself uses `aria-expanded={isExpanded}` and `aria-controls="snapshot-row-{id}-windows"` pointing at the expanded panel.
- Color contrast: every text/background pair listed above is sourced from sibling routes that already ship — no new pairs introduced.
- Focus order: header → sidebar nav → main content (inherent from DOM order; no `tabindex` overrides).

## What This Contract Deliberately Does NOT Specify

These are explicit non-goals. Locked by CONTEXT.md D-10 through D-13 and reaffirmed here so checker doesn't flag their absence as gaps:

- **Calendar / date picker.** Past instants come from external permalinks only.
- **Timeline scrubber / slider.** No range selector; today's list or one permalinked instant.
- **Geometry mosaic / window-rect rendering.** Geometry is shown as text (`1920×1080 @ (0, 0)`), never visualized as a positioned rectangle. Adding a visual mosaic is a deferred phase.
- **Multi-device device selector.** Per-device-only is locked by D-12; no `<select>` for device.
- **Window-title search.** Locked by D-13; no search input on this surface.
- **Live updates / polling.** The page is loaded once on navigation; the user reloads to see new data.
- **Export / download.** No CSV or JSON export of the snapshot list.
- **Toast / banner notification system.** The dashboard does not have one and Phase 7 does not introduce one. Errors render inline; copy-permalink confirmation is in-button text.

If any of these surface during planning or execution, they MUST be rejected by the planner as scope creep.
