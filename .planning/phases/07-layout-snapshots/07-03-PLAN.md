        ```sql
        LIMIT 1
        ```

        ```sql
        SELECT id, captured_at, jsonb_array_length(windows) AS windows_count
        FROM layout_snapshots
        WHERE device_id = $1 AND captured_at >= $2 AND captured_at <= $3
        ORDER BY captured_at ASC
        LIMIT $4 OFFSET $5
        ```

    - `DownsampleTo10Min`: implement as DELETE losers + UPDATE survivor, NOT UPDATE jsonb_set (Pitfall 7). Recommended SQL (single transaction):

        ```sql
        WITH bucketed AS (
            SELECT id,
                   row_number() OVER (
                       PARTITION BY device_id, date_trunc('hour', captured_at)
                                 + (extract(minute FROM captured_at)::int / 10) * interval '10 minutes'
                       ORDER BY captured_at ASC
                   ) AS rn
            FROM layout_snapshots
            WHERE tier = 'raw' AND captured_at < $1::timestamptz - interval '7 days'
        ),
        survivors AS (
            SELECT id FROM bucketed WHERE rn = 1
        ),
        losers AS (
            SELECT id FROM bucketed WHERE rn > 1
        ),
        promoted AS (
            UPDATE layout_snapshots SET tier = '10min' WHERE id IN (SELECT id FROM survivors)
            RETURNING id
        ),
        deleted AS (
            DELETE FROM layout_snapshots WHERE id IN (SELECT id FROM losers) RETURNING id
        )
        SELECT (SELECT count(*) FROM deleted)::bigint;
        ```

        Wrap in `s.pool.BeginTx`/`tx.Commit`. Return the count from the final SELECT (use `tx.QueryRow(ctx, sql, now).Scan(&deleted)`).

    - `DownsampleTo1Hr`: same shape, but PARTITION BY device_id + date_trunc('hour', captured_at), tier filter = '10min', age threshold = 37 days, target tier = '1hr'.

    ```go
    func decodeLayoutJSON(r *http.Request, v any) error {
    ```

    ```go
        // First run after a short delay to let the server settle.
        time.Sleep(30 * time.Second)
        ticker := time.NewTicker(1 * time.Hour)
        defer ticker.Stop()

        run := func() {
            now := time.Now().UTC()
            // 7d -> 10min
            del10, err := s.DownsampleTo10Min(ctx, now)
            if err != nil {
                logger.Warn("layout downsample 10min failed", "error", err)
            } else if del10 > 0 {
                logger.Info("layout downsample 10min", "deleted", del10)
            }
            // 37d -> 1hr
            del1h, err := s.DownsampleTo1Hr(ctx, now)
            if err != nil {
                logger.Warn("layout downsample 1hr failed", "error", err)
            } else if del1h > 0 {
                logger.Info("layout downsample 1hr", "deleted", del1h)
            }
        }

        run() // initial run after delay
        for {
            select {
            case <-ctx.Done():
                return
            case <-ticker.C:
                run()
            }
        }
    }
    ```

## Trust Boundaries

- **client → server (POST):** API-key auth via Authorization: Bearer; payload is JSONB; potentially malicious window titles.
- **dashboard → server (GET):** JWT auth; user-scoped reads; device authorization required.
- **operator deployment → server:** trusted; controls migrations and env.

## STRIDE Threat Register

- **T-7-03-01 — Spoofing (cross-user device access):** A logged-in user calls `GET /api/v1/layout-snapshots?device_id=<other_user's_device>`. Disposition: mitigate. Mitigation: layoutAtHandler + layoutTimelineHandler authorize via `device.UserID == userID` (acceptance criterion). 403 on mismatch.
- **T-7-03-02 — Tampering (privacy field smuggling):** Client POSTs a snapshot with extra fields (pid, cmdline, screenshot_b64). Disposition: mitigate. Mitigation: server-side struct has exactly 6 inner Window fields and re-marshals before storage so unknown JSON fields are silently dropped. Test TestLayoutIngest_PrivacyReject confirms.
- **T-7-03-03 — Information disclosure (window-title leak):** Window titles can contain URLs, file paths, secrets in shell prompts. Disposition: accept. Rationale: same trust posture as existing focus_events which already store titles; user owns their server (per PROJECT.md). Mitigation: dashboard renders titles as text (no HTML eval) — see 07-04-PLAN.
- **T-7-03-04 — Denial of service (oversize payload):** Client sends a 100MB JSON body. Disposition: mitigate. Mitigation: 4MB MaxBytesReader cap (returns 413) — enough for 256 windows × ~200 bytes overhead × 4× margin.
- **T-7-03-05 — Information disclosure (raw SQL injection):** All accessors use parameterized queries via pgx. Disposition: mitigate by codebase pattern; acceptance criterion confirms (pgx is the standard).
- **T-7-03-06 — Tampering (downsampling JSONB UPDATE):** Mistakenly using `UPDATE ... SET windows = jsonb_set(...)` would cause WAL bloat. Disposition: mitigate. Mitigation: downsampling uses DELETE losers + UPDATE tier on survivors only — JSONB column is never mutated. Acceptance criterion grep-checks for `jsonb_set` (must be 0).
- **T-7-03-07 — Denial of service (downsampler runaway):** A bug in the bucketing CTE could delete too many rows. Disposition: mitigate. Mitigation: transactional (BeginTx + Commit) with explicit row_number() partition windows; unit tests TestDownsample_10min and TestDownsample_1hr verify exact survivor counts.
- **T-7-03-08 — Repudiation:** Server logs INFO on every downsample run with delete counts; provides an audit trail.
